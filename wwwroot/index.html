How this app works

M365 Metrics Monitor is a free, local, read-only dashboard. It runs on your own PC, hosts a small web server on localhost, and reads your Microsoft 365 tenant through Microsoft Graph. Nothing leaves the machine except the read-only Graph calls, and there is no account or sign-up. It only ever reads — to change anything you still use the Microsoft admin center.

First-time setup

Auth is app-only (client credentials): no user sign-in, no redirect URI. You register one app in Entra and paste three values into this tool.

  1. Register an app. Entra admin center → App registrations → New registration. Name it (e.g. “M365 Metrics Monitor”), single tenant, no redirect URI.
  2. Add API permissions. Under API permissions, add these Application Microsoft Graph permissions, then Grant admin consent:
    • Organization.Read.All — licences
    • User.Read.All — users, guests
    • Reports.Read.All — storage, workload, Copilot usage
    • Group.Read.All — governance groups
    • Directory.Read.All — app secrets, admin roles
    • ServiceHealth.Read.All — service health, message center
    • SecurityEvents.Read.All — Secure Score
  3. Create a client secret. Certificates & secrets → New client secret. Copy the secret Value immediately — it is shown only once.
  4. Enter it here. Open Settings → Tenants and fill in:
    • Label — a friendly name (e.g. “Contoso Production”)
    • Tenant ID — Directory (tenant) ID
    • Client ID — Application (client) ID
    • Client Secret — the value you copied
    Click Save & connect. The status dot on the tenant pill turns green when live.
  5. Verify. Use Check permissions in Settings to confirm every scope is granted — it flags which tiles won’t work if any is missing.

More than one tenant

Add more tenants in Settings → Tenants, then switch between them from the tenant pill at the top right. Each tenant keeps its own layout and trend history, and its own client secret. When you edit a tenant its secret is shown back masked, with an eye toggle so you can reveal and check it — it never leaves this machine and is only ever sent to Microsoft Graph.

Settings you can tune

  • Cost per licence — Graph does not expose prices, so enter a monthly cost per SKU to turn the Unused Licences tile into real idle spend.
  • SharePoint storage quota — Graph can’t read the tenant quota app-only, so enter it (in GB, TB or PB) from the SharePoint admin center to drive the storage bar and free-space figures.
  • Alert thresholds — the secret-expiry window and storage-warning percent used to highlight tiles.

These live in your browser, as does the theme (light/dark), which is remembered between visits.

Reading the tiles

Tiles marked LIVE are current directory data; ~2D comes from usage reports, about one to two days behind. Trend arrows (▲/▼) under a number appear once the tool has data from more than one day — green means the metric improved, red means it got worse. If a tenant is missing a permission, that one metric simply stays blank and the rest keep working.

Full lists

Click a tile (or a left-nav item) to open the full list behind it — sortable columns, a filter box, paging and Export CSV. On the SharePoint list a note appears if your tenant hides site URLs (the (root) report privacy setting); once that setting is off, real site URLs show as clickable links.

Rearranging

On the Overview, hover a card and drag its top-left handle (mouse or touch) to rearrange it; a Reset layout button appears in the top bar once you’ve changed the order. The arrangement is saved per tenant.

Staying up to date

The version button at the bottom-left checks GitHub for newer releases and shows a download link if one exists. The tool never auto-updates — you stay in control.

What needs extra licensing

Stale accounts and guest inactivity read sign-in activity, which needs AuditLog.Read.All plus an Entra ID P1 licence; without it those two stay blank. Everything else works on the permissions above.
